# ADR-001: Every fixed-form generator ships a self-generated reference artifact

## Status
accepted

## Context
`impulse-artifact` measured its own output against `examples/` — 21 files
vendored from Anthropic's html-effectiveness gallery. That means the skill
was calibrated against someone else's output, never its own. A prose
description of "what good output looks like" drifts from what the skill
actually produces over time, and nothing catches the drift, because there
was no baseline generated BY the skill itself to diff against.

The same gap existed everywhere else a skill produces a fixed, non-creative
form: `impulse-wiki`'s MOCs, `impulse-md-generator`'s syntax coverage,
this skill's own specs/ADRs/changelogs, `impulse-goal`'s templates,
`impulse-clone`'s assessment reports.

## Decision
Every skill that generates a NON-creative, fixed-form deliverable must ship
a reference artifact that satisfies two conditions, both mandatory:

1. **Lives inside the skill** — `references/self-reference.<ext>`, not an
   external link, not a vendored third-party example.
2. **Generated BY the skill itself** — applying its own rules to itself
   (or to a real decision/fact about the suite), not hand-templated to
   look like plausible output.

Creative output (brainstorm panels, review findings, humanizer prose) is
explicitly excluded — there's no fixed form to measure against, a
"reference" would be meaningless there.

## Alternatives considered
- **Keep the vendored gallery as the only calibration reference** —
  rejected: measures the skill against someone else's taste, not its own
  output; drift between "the rule as written" and "the rule as executed"
  goes undetected indefinitely.
- **A prose checklist per skill, no artifact** — rejected: words drift from
  behavior with no mechanical way to notice; an artifact is falsifiable
  (regenerate it, diff), a checklist isn't.
- **One shared example gallery for all skills, not per-skill** — rejected:
  a shared gallery re-introduces the exact "sverified against someone
  else's output" problem this ADR exists to fix, just centralized instead
  of vendored.

## Consequences
**Buys:** a mechanical way to notice drift (regenerate, diff, a difference
is either a skill bug or a stale reference — both visible instead of
silent); an onboarding artifact a human can open and understand the
skill's actual output shape from, not just its prose description.

**Costs:** every fixed-form skill now owns one more file to keep in sync as
its own rules evolve — a reference that stops matching current rules and
never gets regenerated is worse than no reference, because it silently
teaches the wrong shape. `impulse-debt`'s ceiling-marker discipline doesn't
cover this drift risk yet — flagged as open work, not solved by this ADR
alone. No automated check currently catches a stale self-reference;
`scripts/check-skills.js` would need a dedicated rule for that, which does
not exist as of this ADR.
